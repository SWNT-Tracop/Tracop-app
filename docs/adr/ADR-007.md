# ADR-007: PostgreSQL y pg-boss

## Contexto

La plataforma requiere persistencia y trabajos en cola.

## Decisión

Usar PostgreSQL con schema por módulo y pg-boss.

## Operación de pg-boss

- `pg-boss` (12.38.1, MIT, Node `>=22.12.0`) solo se carga en el proceso trabajador (`apps/api/src/worker.ts`); la API HTTP y Jest no lo importan.
- `pg-boss` administra su propio schema `pgboss`: lo crea y lo migra al arrancar. Las migraciones escritas a mano (`apps/api/drizzle`) no lo tocan y `drizzle/migrate.ts` no lo crea.
- El rol de base de datos con el que corre el trabajador necesita `CREATE` sobre la base para crear el schema `pgboss` la primera vez, y después privilegios para mantener sus tablas, secuencias e índices. En despliegues administrados, el rol de migraciones debe conceder al rol del trabajador los privilegios mínimos sobre `pgboss`.
- Cada trabajo usa una cola con política `singleton`, de modo que haya como máximo una ejecución activa por trabajo aunque corran varios trabajadores; los crons se evalúan en UTC.

## Consecuencias

No se usa Redis ni broker; PostgreSQL es suficiente para el piloto. Ver [ADR-016](ADR-016.md) para los trabajos y el despachador del outbox.

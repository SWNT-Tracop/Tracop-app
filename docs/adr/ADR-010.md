# ADR-010: Núcleo de catálogo

## Contexto

El piloto necesita un catálogo de categorías, productos y lotes que permita publicar y descubrir oferta con campos estructurados. La implementación actual debe validar lotes dentro de Colombia, filtrar ofertas vigentes, restringir datos de ubicación y limitar el volumen de búsquedas sin añadir infraestructura de rate limiting.

## Decisión

- El módulo `catalog` es dueño de categorías, productos, lotes y fotos de lote, con dominio, aplicación, puertos y adaptadores. Los cambios de estado de lote se escriben en el outbox compartido.
- Las unidades aceptadas por el catálogo quedan limitadas provisionalmente a `kg`, `g`, `lb`, `und`, `docena`, `arroba`, `quintal`, `caja`, `mano` y `bulto`. Esta lista es el vocabulario implementado, no una decisión de negocio definitiva.
- `qualityGrade` es texto opcional, limitado a 100 caracteres. No se impone un vocabulario de grados de calidad.
- Las coordenadas de lotes se validan dentro de los límites de Colombia. Las respuestas REST omiten latitud y longitud salvo cuando el viewer es el proveedor dueño del lote.
- La búsqueda requiere autenticación, aplica límites de radio configurables y usa `InMemorySearchRateLimiter`, por usuario autenticado. Los contadores son locales al proceso y reinician al reiniciar la API.
- La búsqueda de lotes pagina con cursor/keyset basado en la ordenación solicitada y el ID del lote como desempate; el cursor REST se cifra y autentica con una clave derivada de `JWT_SECRET`.
- El adaptador de catálogo obtiene resúmenes públicos de proveedores mediante `ProviderDirectoryPort`; `bootstrap/` lo implementa con `IdentityProviderDirectoryAdapter` que delega a `ProviderProfileService` de `identity`, sin consultar sus tablas.

## Consecuencias

- El catálogo ofrece búsqueda y publicación estructuradas mientras conserva el aislamiento entre módulos y la privacidad de coordenadas para terceros.
- La lista provisional de unidades puede requerir ampliación o revisión; las reglas de vocabulario de `qualityGrade` siguen pendientes y no se deben inferir de la longitud máxima.
- El rate limit en memoria es sencillo y no requiere Redis ni almacenamiento compartido, pero no coordina cuotas entre varias instancias ni sobrevive a reinicios.
- Los cursores no exponen directamente los criterios de ordenación, y dependen de `JWT_SECRET`; rotar ese secreto invalida cursores previamente emitidos.
- La búsqueda puede recorrer un conjunto amplio de resultados en la aplicación para formar páginas; el patrón actual prioriza una interfaz estable con cursor, no promete un motor de búsqueda geoespacial especializado.
